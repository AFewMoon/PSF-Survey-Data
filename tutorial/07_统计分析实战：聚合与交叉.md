# 第 7 章 统计分析实战：聚合与交叉

> 目标：精读 `plot_survey.py` 的四个聚合函数——单选按年聚合、多选组按年聚合、Top N 选取、跨变量交叉。这是统计概念（第 6 章）落到 pandas 代码的地方。

## 7.1 数据读取：按需加载

```python
def load_master() -> pd.DataFrame:
    """按需读取 master 表（usecols 控制内存），year 转为 int。"""
    usecols = ["year"] + SINGLE_COLS + [c for cs in MULTI_GROUPS.values() for c in cs]
    df = pd.read_csv(MASTER, encoding="utf-8-sig", keep_default_na=False, usecols=usecols)
    df = df[df["year"].astype(str).str.strip().ne("")].copy()
    df["year"] = df["year"].astype(int)
    return df
```

三个工程细节：

- **`usecols` 白名单**：master 154 列，绘图只用 20 来列。按需读取让内存占用降一个数量级，也让脚本对"加列不破图"免疫。
- **`keep_default_na=False` 一以贯之**：与清洗/对齐约定一致，缺失是空串不是 NaN。
- **`year` 列的防御性清洗**：先按字符串过滤空值再转 int。若 master 尾部混入空行（CSV 追加错误等），`astype(int)` 会当场崩溃——先把空串挡掉，转换才安全。`.astype(str).str.strip().ne("")` 比 `!= ""` 多容忍首尾空白。

列清单本身是配置：`SINGLE_COLS`（5 个单选列）、`MULTI_GROUPS`（3 个多选组，每组是显式列名清单）。显式列出而非 `startswith("database.")` 动态匹配——**多选组的列集必须固定**（图 5–7 的 Top N 排名要求各年比较同一选项集），动态匹配会因某年缺列而悄悄改变口径。

## 7.2 单选题按年聚合

```python
def agg_single_by_year(df: pd.DataFrame, col: str, canon: dict[str, str] | None = None
                       ) -> tuple[pd.DataFrame, pd.Series, pd.Series]:
    """单选题按年聚合。

    返回 (占比表[行=年份, 列=类别, 单位 %], 各年有效样本数, 各年缺失率 %)。
    canon: 取值归并映射；空字符串视为缺失。
    """
    v = df[col].replace("", np.nan)
    if canon is not None:
        v = v.map(canon)
    year = df["year"]
    valid = v.notna()
    tab = pd.crosstab(year[valid], v[valid], normalize="index") * 100
    tab = tab.reindex(index=YEARS, fill_value=0.0)
    n = valid.groupby(year).sum().astype(int).reindex(index=YEARS, fill_value=0)
    miss = (1.0 - valid.groupby(year).mean()).reindex(index=YEARS, fill_value=np.nan) * 100
    return tab, n, miss
```

五行代码，五个决策：

**（a）空串 → NaN 是口径切换点。** 全库约定"缺失=空串"，但统计时 pandas 的 `crosstab(normalize=...)` 按"非 NaN"算分母。把空串换成 NaN 是把**存储约定翻译成统计口径**——这一步只发生在聚合函数内，落盘前后仍是空串。注意 `replace("", np.nan)` 要在 `map(canon)` **之前**：`canon` 字典里没有空串键，若先 map，空串会变成 NaN（map 对未知键默认产出 NaN）效果碰巧相同，但语义上先明确缺失再映射更清晰，且避免 canon 值意外撞上空串键。

**（b）`canon` 是展示层归并**。`MAIN_LANG_CANON` 把 "Yes"/"No, I use Python as a secondary language"/"No, I don't use Python for my current projects" 归并成三个中文口径。与对齐层的归并（第 5 章）分工不同：对齐层统一**跨年拼写**，展示层归并**分析口径**（如把英文文案译成中文、把相邻档位合并）。两层都必须有显式字典，禁止在绘图函数里内联 `if`。

**（c）`normalize="index"` 的分母是有效样本**。`year[valid], v[valid]` 先把缺失行剔除再交叉，每行（年份）归一化到 100%。这正是第 6 章口径红线：缺失者不进分母。若写成 `pd.crosstab(year, v.fillna("缺失"))` 再画堆叠图，缺失会变成一个"类别"挤占 100% 空间——适合展示缺失本身，不适合展示结构占比。两种画法都合法，**但要选一个并在脚注里说明**。

**（d）`reindex(index=YEARS, fill_value=0.0)` 的双保险**。某年全缺失（valid 全 False）时 `crosstab` 会缺该行，reindex 补零保证下游绘图拿到完整 5 行；`n` 补 0、`miss` 补 NaN（"无有效样本"与"有效样本 0% 缺失"不同——前者根本没数据，缺失率无定义）。

**（e）三个返回值一起走**：占比表 + 各年 n + 各年缺失率。n 和缺失率不参与绘图主体，全部进脚注（第 8 章 `_footnote`）——**统计数字不带样本量就是耍流氓**，函数签名从结构上强制了这个纪律。

## 7.3 多选题组按年聚合

```python
def agg_multi_by_year(df: pd.DataFrame, group: str
                      ) -> tuple[pd.DataFrame, pd.DataFrame, pd.Series, pd.Series]:
    """多选题组按年聚合。

    返回 (使用率表[行=选项, 列=年份, 单位 %], 人数表[行=选项, 列=年份],
          各年有效样本数, 各年缺失率 %)。
    有效样本 = 该组至少勾选一项（含 None）的受访者。
    """
    cols = MULTI_GROUPS[group]
    any_sel = (df[cols] == 1).any(axis=1)
    year = df["year"]
    rates = df.groupby("year")[cols].mean().reindex(index=YEARS).T * 100
    counts = df.groupby("year")[cols].sum().reindex(index=YEARS).T.astype(int)
    n = any_sel.groupby(year).sum().astype(int).reindex(index=YEARS, fill_value=0)
    miss = (1.0 - any_sel.groupby(year).mean()).reindex(index=YEARS, fill_value=np.nan) * 100
    return rates, counts, n, miss
```

对照第 6 章的口径表逐条落实：

- **分母 = 组有效样本**：`any_sel = (df[cols] == 1).any(axis=1)`——至少勾选一项（包括勾了 None）的人。`groupby("year")[cols].mean()` 的分母是**全体受访者**（0/1 列 mean = 勾选人数 / 总人数），这里有个隐蔽的口径差：mean 的分母不是 any_sel 人数！

  为什么可以接受？因为 master 表由共有列构成，未作答该组的受访者所有选项列都是 0（勾选标记缺失），mean 分母偏大、使用率被**等比例稀释**。`_multi_chart` 绘图时展示的是这种"全体分母"的使用率，而脚注里的 `n`/`miss` 用 any_sel 口径提示读者"只有 X% 的人看到过这道题"。**两种口径并存但各司其职**：图内数字跨年可比（分母定义统一），脚注解释为什么数字看起来偏低。若要严格的"作答者内使用率"，把 `df.groupby("year")[cols].mean()` 改成 `df[any_sel].groupby("year")[cols].mean()`——但那样各年分母不同会放大缺失率的口径噪声，本项目选择前者并显式注明。理解这个取舍比记住代码重要。

- **counts 与 rates 平行**：人数表用于图上标注"26.5%（6,720人）"——百分比 + 绝对人数双标注，读者可自行评估小样本格的可靠性。

- **`.T` 转置的约定**：多选返回"行=选项、列=年份"，与单选的"行=年份、列=类别"相反。各自贴合下游绘图函数的输入习惯（堆叠图按年堆叠、分组条形按选项分行）。**约定写进 docstring**，调用方不用猜。

## 7.4 Top N 选取：排除 None

```python
def top_options(rates: pd.DataFrame, n_top: int = 10) -> list[str]:
    """按跨年总均值排序取 Top N（排除 *.None 选项）。"""
    ranked = rates.mean(axis=1).sort_values(ascending=False)
    ranked = ranked[~ranked.index.str.endswith(".None")]
    return list(ranked.head(n_top).index)
```

两个决策：

1. **排序依据是跨年总均值**（5 年平均使用率），不是最后一年。用总均值选出的选项集对"趋势展示"更稳定——不会因某年异常值挤进/挤出榜单而改变可比集。
2. **排除 None**：`"不使用任何数据库"` 不是工具，混进 Top 10 会让"PostgreSQL 使用率排名"这类解读失真。`.endswith(".None")` 依赖列名规范（`database.None`）——又一个"列名规范是全局契约"的例子。

Top N 之外的选项没有丢弃而是**显式不展示**（图上只有 Top 10 条），与分析报告里"其余框架使用率都在 4% 以下"的表述呼应：**省略要可被读者察觉**，脚注注明"仅展示 Top 10（按 5 年均值）"。

## 7.5 跨变量交叉：年限 × 用途热力图

第 8 张图把两个单选变量交叉：

```python
exp = df["years.of.coding"].replace("", np.nan).map(YEARS_EXP_CANON)
use = df["use.python.most"].replace("", np.nan).map(USE_CASE_CANON)
valid = exp.notna() & use.notna()          # 两个变量都有效才算样本
tab = pd.crosstab(exp[valid], use2[valid], normalize="index") * 100   # 行内占比
```

三个口径细节：

- **`valid = exp.notna() & use.notna()`**：交叉分析的有效样本是"两变量都答了"的交集（实测 108,648）。两个变量各有 20%–48% 缺失，交集可能比单独任一变量小得多；脚注必须写交集 n。若缺失机制是 MAR 且缺失原因不同，交集样本的构成会进一步偏移——报告对此明示"行内占比"只是描述性结果。
- **`normalize="index"` 行内占比**：每行（年限组）合计 100%，回答"在 3–5 年经验的人里，多少比例做 Web 开发"。**列内占比会回答另一个问题**（"做 Web 开发的人里多少是新手"），两者不可混用——新手人数占比高也可能因为新手总量大。选行内占比是因为分析问题是"经验如何影响用途"，经验是条件变量。
- **Top 8 + 其他合并**：`use2 = use.where(use.isin(top), "其他（合并）")`——类别太多时热力图不可读，尾部合并成"其他"并保留在图上（不隐藏），读者知道合并发生。

## 7.6 聚合函数的共性纪律

四个函数共享的设计纪律，值得抄到任何统计代码里：

1. **缺失口径显式化**：空串→NaN 的翻译点只在函数入口一行。
2. **归并走显式字典**：`MAIN_LANG_CANON`、`PURPOSE_CANON`、`USE_CASE_CANON`、`YEARS_EXP_CANON` 全是模块级常量，可 diff、可审计。
3. **有序类别显式排序**：`YEARS_EXP_ORDER` 保证"不足 1 年 → 11 年以上"的有序轴不被 pandas 按字典序打乱（"11 年以上"字典序会排在"1–2 年"前面！）。
4. **样本量与缺失率作为第一公民返回**：进脚注、进 print 摘要，不留在调用方手工补。
5. **纯函数**：传入 df 返回新结构，不改入参（AGENTS.md 编码规范）——聚合结果可以被安全复用与并测。

import pandas as pd
m = pd.read_csv("aligned/survey_2019_2023_master.csv", encoding="utf-8-sig",

分母是 2019 年答了此题的人数（约 47,308 × 74.5% ≈ 35,000），非全体 2019 受访者。

**7.2** `tab.columns` 来自数据出现顺序/字典序，"11 年以上"（yī 一开头 11）按 Unicode 排序在 "1–2 年" 前、甚至可能在 "3–5 年" 前，堆叠顺序错乱。修复一：字典 `YEARS_EXP_CANON` + 调用方传 `order=[...]`（本项目方案，简单直接，但依赖调用方记得传）；修复二：`exp = exp.astype(pd.CategoricalDtype(order, ordered=True))`，crosstab 自动按类别序排（一劳永逸，但类别清单要提前定义）。数据量小、类别固定时二选一皆可；类别动态时方案二更稳。

**7.3** 参考实现：

```python
def usage_rate_among_respondents(df: pd.DataFrame, group: str) -> pd.DataFrame:
    cols = MULTI_GROUPS[group]
    any_sel = (df[cols] == 1).any(axis=1)
    return (df[any_sel].groupby("year")[cols].mean().reindex(index=YEARS) * 100).T
```

与全体分母版本对比：全体分母 = 作答者分母 × (1 − 缺失率)。2023 年组缺失 33.8%，故作答者口径的使用率约为全体口径的 1/(1−0.338) ≈ 1.51 倍（如 PostgreSQL 29.3% → 约 44%）。方向：作答者口径数字一律更高（分母更小）。跨年比较时作答者口径会放大缺失率波动带来的分母噪声（2022 缺 23.8% vs 2023 缺 33.8%），这正是本项目选全体分母 + 脚注提示的原因。

**7.4** 以 2023 年排序会把 2023 年才冒头/或 2023 年因缺失率升高而被稀释的选项排进去（2023 缺失 55.4%，使用率整体被稀释约 1/2.2，榜单结构性偏向"2023 年缺失率低时本就靠前"的选项——方向难以预测）。跨年总均值更稳：不受单年口径波动绑架。判断标准：**榜单选择标准不应与要展示的年份维度相关**，否则 Top N 的选择本身引入趋势偏差（选择效应）。

**7.5** 列内占比回答"做数据分析的人里，各年限组占多少"。由于各年限组人数不同（3–5 年组人数多），列内占比会偏向人多的组，且"数据分析"行解读完全翻转：从"数据分析在各年限组都在 15%–17%"变成"数据分析用户中 X% 是 3–5 年经验者"——后者混合了组人数差异与真实倾向。辛普森视角：当条件变量（年限）与样本构成相关时，列内占比把构成效应混入效应估计；行内占比固定组内人数做归一，直接估计 P(用途 | 年限)，才是"经验如何影响用途"的条件概率方向。
