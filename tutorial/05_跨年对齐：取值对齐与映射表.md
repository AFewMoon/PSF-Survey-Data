# 第 5 章 跨年对齐：取值对齐与映射表

> 目标：理解 `align_survey.py` 的取值对齐——变体收集、自由文本保护、标准值选取，以及 `value_mapping.csv` 的设计与使用。列名对齐让"列"可比，取值对齐让"单元格"可比。

## 5.1 取值差异从哪来

清洗与列名对齐之后，还剩最后一层不一致：**同一列里的取值文案跨年不同**。实测来源有四类：

1. **措辞演进**：`main.purposes` 一题 2019–2022 年是 "For work" / "For personal, educational or side projects" / "Both for work and personal"，2023–2024 年变成 "Work" / "Personal, educational, or side projects" / "Both for work and personal projects"。注意：**这类差异本层并不自动归并**（"forwork" 与 "work" 归一键不同），而是在分析层用显式映射兜住（`plot_survey.py` 的 `PURPOSE_CANON`）——口径写在代码里、可审查，代价是必须有人记得写。
2. **标点/空白异体**：清洗层已归一掉大部分，但漏网的会在取值层体现（如弯引号 `’`、`e_g_` 这类下划线替换、多余空白）。
3. **缩写差异**：`AWS` / `Amazon Web Services`（由 `OPTION_ALIASES` 处理，见第 4 章）。
4. **真语义差异**：2023–2024 年新增选项（"Data engineering"、"Academic research" 等）——**这类不是变体，不能合并**，取值对齐对它们必须无操作。

取值对齐的目标：前三种归并成标准文案，第四种原样保留并显式记录。

## 5.2 变体收集：三重保护

```python
def align_values(dfs: dict[int, pd.DataFrame]) -> tuple[dict[int, pd.DataFrame], pd.DataFrame]:
    """统一类别列取值文案；二值列(0/1)与自由文本列(基数>60)不处理。"""
    rows: list[dict] = []
    # 跨年取值变体：(标准列名, 归一键) -> {year: 原值}
    variant_pref: dict[tuple[str, str], dict] = {}
    for year in YEARS:
        for col in dfs[year].columns:
            s = dfs[year][col]
            if s.dtype.kind in "bi" or s.nunique(dropna=False) > 60:
                continue                              # 保护一、二
            for v in s.dropna().unique():
                v = str(v).strip()
                if not v or norm_key(v).startswith("otherplease"):
                    continue                          # 保护三
                variant_pref.setdefault((col, norm_key(v)), {}).setdefault(year, v)
```

**保护一：二值列跳过**（`dtype.kind in "bi"`）。多选题已是 0/1 整数，选项文本在列名里，取值层无事可做。

**保护二：自由文本列跳过**（`nunique > 60`）。"其他 - 请写出"之类的开放题有数千种回答，基数阈值 60 把它们挡在映射之外——给自由文本建映射表既不现实也不该做（没有"标准答案"）。60 这个阈值是经验值：真实单选题的选项数远低于它（一般 < 30），而自由文本动辄上千；阈值只需落在两者之间。注意 `nunique(dropna=False)` 显式不去缺失——缺失（NaN）也算一种取值，但不参与映射（下一段的 `dropna().unique()` 再滤掉）。

**保护三：其他自填跳过**（`norm_key(v).startswith("otherplease")`）。有的年份把自填框挂在 "Other - please specify" 选项下，归一键以 `otherplease` 开头的一律不进映射。

`variant_pref` 的键是 `(标准列名, 归一取值键)`，值是 `{年份: 原值}`——与列名对齐的等价类结构同构，只是维度从"跨年列"换成"跨年取值"。

## 5.3 标准值选取：新年份优先（再次）

```python
    canon_value: dict[tuple[str, str], str] = {}
    for (col, key), by_year in variant_pref.items():
        best = next((by_year[y] for y in reversed(YEARS) if y in by_year), next(iter(by_year.values())))
        canon_value[(col, key)] = canonical_option(best)
```

逐层拆解这一行：

- `reversed(YEARS)`：从 2024 往 2019 找。
- `next((by_year[y] for y in reversed(YEARS) if y in by_year), ...)`：取**最新出现该归一键的年份**的原值。
- 兜底 `next(iter(by_year.values()))`：理论上不会触发（能进 `variant_pref` 的键至少有一年），防御性写法。
- 最后过 `canonical_option`：先查 `OPTION_ALIASES`（缩写→全称），未命中走 `norm_text`（压标点空白）。

与列名对齐（第 4 章）的原则完全一致：**标准值取最新年份写法**。两处独立实现同一个原则——这是刻意的重复还是应抽取公共函数？本项目的回答：结构相似但输入形态不同（列名变体 dict vs 取值变体 dict），且各处都要贴合自己的数据结构，保留两份十行的实现比强行抽象一个带回调的通用函数更可读。抽象的门槛是"重复造成维护负担"，不是"重复本身"。

## 5.4 应用映射与生成映射表

```python
    for year in YEARS:
        df = dfs[year].copy()
        for col in df.columns:
            s = df[col]
            if s.dtype.kind in "bi" or s.nunique(dropna=False) > 60:
                continue
            def conv(v, _col=col):                    # 注意默认参数绑定列名
                v = str(v).strip()
                if not v:
                    return v
                c = canon_value.get((_col, norm_key(v)))
                if c is not None and c != v:
                    rows.append({"year": year, "column": _col, "original": v, "canonical": c})
                    return c
                return v
            df[col] = s.map(conv)
        aligned[year] = df
    return aligned, pd.DataFrame(rows)
```

四个细节：

1. **`_col=col` 默认参数绑定**：闭包里引用循环变量的经典坑——若写 `c = canon_value.get((col, ...))`，`conv` 捕获的是循环变量本身，所有列共用最后一次的 `col`。用默认参数在定义时固化绑定，是 Python 闭包的标准规避手法。
2. **`c != v` 才记录**：映射表只记录**实际发生**的替换，包括"归一键相同但文本被 `norm_text` 压过"的情形。未变化的取值不进表，保持 `value_mapping.csv` 精简可读。
3. **替换是"按键替换文本"而非重编码**：类别值仍是文本，没有转 category 码。这是为了对齐报告可读性；若下游要建模，可再统一 `astype("category")`。
4. **`s.map(conv)`** 逐格调用 Python 函数，对百万级单元格偏慢；类别列基数小，可先用 `value_counts` 拿到唯一值清单、构建 `map` 字典再 `s.map(dict)`——本项目未做此优化（一次性管线），但你要在大表上做时应知道这个路径。

规模感：109,745 行记录，但去重后只有 **49 种**不同的替换规则——说明清洗层已经吃掉了绝大多数变体，取值层处理的是"漏网之鱼"。这一落差本身就值得记住：**对齐报告里的行数看着惊人，实际语义变更极小**。

三个用途：

1. **审计口径**：分析报告 2.3 节"跨年口径差异"的全部论据都出自这张表——分析前先通读它，知道哪些对比是"被归并出来的"。
2. **排查异常**：统计图里某类占比跳变时，先查 `value_mapping` 有无对应列的记录，区分"真实趋势"与"归并副作用"。
3. **回溯原始值**：canonical 是丢失信息的（合并后的），original 保留了对齐前的原文。任何精细分析需要原始措辞时，以此表回溯。

`alignment_report.md` 汇总三组数字：列名重命名 382 条（2019 占 201 条）、取值统一 109,745 条、跨年共有列 42 → 153。

## 5.6 纵向合并：master 表

```python
common = sorted(set.intersection(*(set(dfs[y].columns) for y in YEARS)))
master = pd.concat(
    [dfs[y].assign(year=y)[["year"] + common] for y in YEARS], ignore_index=True
)
```

关键决策：**master 只保留跨年共有列，丢弃其余**。

- 为什么不外连接（`pd.concat(join="outer")`）保留全部列？六年的列并集有两千多列，外连接得到的是"绝大多数格全空"的稀疏宽表：读取更慢，且"某列哪些年有值"的元信息只能靠人脑记。**显式丢列 + 分年文件保留全列**的组合，让 master 保持稠密可用，细节回分年文件查。
- `assign(year=y)` 在合并前打上来源标签——所有跨年分析的第一分组键。
- `ignore_index=True` 重置全局行索引；`response_id` 只在年内唯一，跨年不保证，master 里禁止把它当主键用（需要唯一键时用 `(year, response_id)` 复合键）。

最终 master：185,632 行 × 154 列（含 `year`），这就是 `plot_survey.py` 与分析报告的唯一数据源。分年行数：47,308 / 37,793 / 23,201 / 23,009 / 25,324 / 28,997。

## 5.7 本章要点

- 取值对齐处理"同一列内跨年文案不一致"，四类来源中只有变体可归并，新增选项绝不能合并。
- 三重保护：二值列、自由文本（基数>60）、其他自填。
- 标准值选最新年份写法，与列名对齐原则一致。
- 闭包循环变量用默认参数绑定；映射表只记录实际发生的替换。
- master 只留共有列、带 `year` 标签；`response_id` 跨年不唯一。
- `value_mapping.csv` 是口径争议的最终仲裁者。

### 参考答案

**5.1** 提到 500：某些基数中等的半自由题（如"你通过什么渠道学习 Python"含自填变体）会被拉进映射，标准值由最新年份"赢者通吃"，几百个稀有变体被并进高频文案——看似简化实则把低频回答**无声地重分类**了，且映射表膨胀到难以人工审读。降到 10：许多正常的多选项单选题（选项 > 10 个，如数据库题 2024 年有 24 个选项）被误判为自由文本而跳过对齐，跨年措辞变体漏网，总表里出现重复语义的类别。教训：阈值是分类器，选错方向要么误杀要么漏放；设定后应输出"被跳过列清单"人工抽查。

**5.2** 两列取值归一键相同（`academicresearch`），进同一等价类，标准值取最新年份文本——**语义不同的两个选项被合并了**。这暴露自动对齐的根本局限：它只看拼写，不看语义。`OPTION_ALIASES` 无法表达"同名不同义"。防线只有人工：映射表（`value_mapping.csv`）把这次合并显式记录出来，审计时若发现可疑合并（同列跨年取值数骤减、某选项占比突增），回查分年数据验证。这正是"分析前先通读 value_mapping"流程存在的原因。

**5.3** 参考实现：

```python
def align_values_fast(dfs, canon_value, YEARS):
    rows: list[dict] = []
    aligned = {}
    for year in YEARS:
        df = dfs[year].copy()
        for col in df.columns:
            s = df[col]
            if s.dtype.kind in "bi" or s.nunique(dropna=False) > 60:
                continue
            uniq = {v: str(v).strip() for v in s.unique()}
            repl: dict[str, str] = {}
            for raw, v in uniq.items():
                if not v:
                    continue
                c = canon_value.get((col, norm_key(v)))
                if c is not None and c != v:
                    repl[raw] = c
                    rows.append({"year": year, "column": col, "original": v, "canonical": c})
            if repl:
                df[col] = s.map(lambda x, _r=repl: _r.get(x, x))
        aligned[year] = df
    return aligned, pd.DataFrame(rows)
```

等价性注意：原实现逐格 `str(v).strip()`，字典版先对 `s.unique()` 归一，`repl` 键是原始值、映射目标已 canonical；断言方式为两版 `df[col].equals()` 与 `rows` 按 `(year, column, original, canonical)` 排序后逐行比对。

**5.4** 外连接总表中，非共有列在其不存在的年份为全空。出错场景：计算"各年使用过至少一种数据库的人的比例"这类"任一非空"指标时，外连接会把"该年没有此题"与"该年没人选此选项"混为一谈——分年文件里数据库组缺 2019 部分选项，外连接下这些年在该列全空，`notna()` 统计会被错误拉低，结论变成"数据库使用率骤降"的假象。内连接迫使分析者只用"年年都有的列"，把口径风险挡在数据结构层。

**5.5** 打开 `value_mapping.csv` 筛 `column == "main.purposes"`，可见 "For work"→"Work"、"Both for work and personal projects"→"Both for work and personal" 之类的跨年归并。对照 4.2 节：结论"工作档稳定在 19%–21%"依赖三档归并（`plot_survey.py` 的 `PURPOSE_CANON` 又做了中文口径归并），若 2019 年 "For work" 的措辞边界与 2020 年 "Work" 略有不同（如当年含兼职），归并会吞掉这个差异。评估结论：三档粗粒度归并下趋势方向可信，但 1–2 个百分点级别的跨年差值不应过度解读——与报告"工作用途几乎没动"的谨慎表述一致。
