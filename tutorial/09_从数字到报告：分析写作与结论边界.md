# 第 9 章 从数字到报告：分析写作与结论边界

> 目标：把前三章的产出（干净的表、稳健的统计、清晰的图）组织成一份经得起追问的分析报告。范本是 `analysis/analysis_report.md`——本章逐节拆解它的结构决策与措辞纪律。

## 9.1 报告的结构：先交代可信度，再给结论

`analysis_report.md` 的八节结构值得作为模板：

```
1. 数据概况        —— 样本量、数据管线一页纸
2. 数据质量与口径差异 —— 原始数据问题、缺失率表、口径差异清单
3. 核心发现        —— 8 条，每条带数字
4. 分主题趋势      —— 每主题：图 + 数字 + 谨慎解读
5–6. 专题分析      —— 编辑器格局、交叉热力图
7. 结论            —— 一段话图景 + "哪些结论最扎实"
8. 注意事项        —— 5 条自律声明
```

反直觉但关键：**第 2 节（数据质量）放在核心发现之前**。读者先知道"2019 年缺 25%""2023 年拆了选项"，再读趋势数字时自带折扣；若把免责声明压到最后，前面的数字已被当作事实消化。报告的顺序就是论证的顺序：**可信度声明 → 结论 → 边界**。

## 9.2 核心发现的写法：数字 + 方向 + 限定

看第 3 节的真实条目：

> 1. Python 的主力地位在加强。主要用 Python 的受访者从 2019 年的 79.5% 升到 2023 年的 85.2%，副语言比例基本稳定在 15% 左右。
>
> 4. Web 开发仍是最主要的单一用途，但不再突出。从 26.3% 降到 22.1%，其中 2023 年的降幅有一部分是选项拆分造成的。

拆解句式："**判断句（主语+方向）+ 首尾数字 + 限定语**"三段式：

- 判断句给结论（"主力地位在加强"）——读者扫一遍加粗判断就能带走全图景；
- 数字给出处（79.5% → 85.2%）——可回查；
- 限定语标折扣（"有一部分是选项拆分造成的"）——不藏不利信息。

对照反例："Web 开发使用率显著下降"——没有数字、没有方向限定、没有混淆因素。"显著"一词在第 6 章已讲过：没做检验就别用统计学术语。

**排序也有讲究**：8 条发现按"结论扎实程度"大致降序（主语言地位最硬 → 编辑器格局受最高缺失率干扰最软）。读者时间有限，先读最可信的。

## 9.3 解读的纪律：从数字到解释的鸿沟

第 4.2 节的一段示范了"数字 → 解释"的正确距离：

> 变化集中在「兼顾」和「个人」两档之间：兼顾从 58.3% 一路降到 51.6%，个人从 21.0% 升到 27.7%，工作档稳定在 19%–21%。一个说得通的解释是疫情期间及之后，学习、副业和教学场景的受访者增多，摊薄了「兼顾」的份额；问卷没有收集职业信息，这一点只能作为猜测保留。

三个动作：**给数字**（三档首尾值）、**给假说**（疫情后学习者增多）、**给假说的边界**（问卷没收集职业信息，"只能作为猜测保留"）。

数据报告中最常见的三种越界，对照本项目怎么防：

| 越界 | 典型句式 | 本项目的处理 |
|---|---|---|
| 相关当因果 | "个人用途上升是因为疫情" | "一个说得通的解释……只能作为猜测保留" |
| 把口径效应当趋势 | "Web 开发在退潮" | "回落幅度和该组缺失率的变化同步，更可能是分母变化而非真实使用率下降" |
| 噪声当发现 | "MySQL 微降 0.3%，值得警惕" | 缺失率可解释范围内的波动不单列；真异常（MySQL 2023 掉 7.7pp）才"值得关注后续年份" |

第三条尤其考验判断力：**什么值得写进报告**。规则是差异幅度与已知的口径噪声（缺失率变化、CI 宽度、选项拆分）比较——超过噪声的地板才值得一条发现，否则并入"基本稳定"。

## 9.4 缺失率的处理：每张表都带着走

第 2.2 节的缺失率表是全报告的锚：

| 题目 | 2019 | 2020 | 2021 | 2022 | 2023 |
|------|------|------|------|------|------|
| is.python.main | 25.5% | 0.2% | 0% | 0% | 0% |
| use.python.most | 48.2% | 24.9% | 21.1% | 20.5% | 24.2% |
| ide.editor（组） | 60.9% | 43.6% | 43.5% | 40.6% | 55.4% |

每个分主题解读都回指这张表（4.5 节："回落幅度和该组缺失率的变化（22.5% → 34.1%）同步"）。写作要点：

- 缺失率**逐年给出**而非给个总数——跨年比较的伤害来自缺失率**差异**，不是缺失率本身。
- 给出**机制解释**："当年问卷把这些题放在选答分支里"（第 6 章的 MAR 判断），读者才知道这不是数据损坏。
- 对缺失最重的主题（IDE 组 40%–60%），直接改口径："把它当作**作答者中的相对位置**更稳妥"——承认某些数字只能比排名不能比幅度。

## 9.5 结论分级：什么最扎实

第 7 节的收尾是全报告最有价值的一段：

> 需要注意，这些结论里最扎实的只有两三条：主语言比例上升、用途向个人侧倾斜、PostgreSQL 领先。其余发现要么受缺失率干扰（多选题组、Web 开发趋势），要么受 2023 年选项拆分影响（领域分布），只能算方向性观察。

把结论分三档：

1. **可断言**（缺失 < 1%、趋势 > 噪声 5 倍、口径无变化）：主语言比例上升（+5.7pp，2020 起缺失 < 0.2%，逐年单调）。
2. **方向性观察**（趋势方向一致但受口径干扰）：PostgreSQL 上升（+5.7pp 但各年缺失 23%–50%）、用途向个人侧倾斜。
3. **存疑线索**（变化幅度在噪声量级或机制未明）：MySQL 2023 回落（超出缺失率可解释范围，但机制未知，"值得关注后续年份"）。

分级标准公开写出来（哪些指标算"扎实"），读者才能自行判断后面新发现该放进哪一档。**报告的说服力不来自没有不确定，而来自不确定被明确标价。**

## 9.6 注意事项：给二次使用者的契约

第 8 节五条（自报抽样、多选超 100%、缺失不随机、口径差异、四舍五入）面向的是**拿这份报告做引用的人**。写作视角转换：不再是"我做了什么"，而是"**你若引用，必须知道什么**"。对应的机制支撑：

- 口径差异条目回指 `value_mapping.csv`（"做更细的分析前建议先过一遍"）——注意事项不是口头警告，要指到可核查的产物。
- 四舍五入声明（"个别表格合计可能不等于 100.0%"）防止读者拿 Excel 复核时误以为发现 bug。

## 9.7 图文配合

报告 4–6 节的模式：**图 → 3–5 句解读 → 与缺失率/口径的勾连**。图的选取遵循第 8 章选型，报告不重复图上的所有数字，只讲**图看不出来的事**：

- 图能看出：Flask 和 Django 前二（条形长短）。
- 图看不出来的，写进文字："回落幅度和该组缺失率的变化同步，更可能是分母变化"——需要第 2 节缺失率表与图的交叉印证。
- 文字给出解读方向，脚注与第 8 节守住边界。

一个反模式是文字复述图上每个数字（"2020 年为 33%，2021 年为 37%……"）——读者会学会跳过你写的所有段落。

## 9.8 复盘：整个项目的方法论闭环

九章走完，回头看全链路：

```
原始 CSV（第1章体检，发现空行/表头差异/多选形态）
   ↓ clean_survey.py（第2-3章：缺失口径、去空去重、列名统一、多选二值化、类型转换）
cleaned/ + cleaning_report.md
   ↓ align_survey.py（第4-5章：归一函数、组路径、等价类、取值归并、master 合并）
aligned/ + column_mapping.csv + value_mapping.csv + alignment_report.md
   ↓ plot_survey.py（第6-8章：口径纪律、聚合函数、三类图型、脚注规范）
charts/ ×8 + 终端摘要
   ↓ 分析写作（第9章：可信度前置、发现分级、边界标注）
analysis/analysis_report.md
```

四条贯穿全程的工程原则：

1. **口径一致**：缺失=空串、UTF-8-BOM、`keep_default_na=False`、新年份优先——所有约定在管线间传递，从未中途变更。
2. **映射外置**：语义决策（组路径、同义词、展示归并、口径三档）全在字典/映射表里，逻辑与数据分离，扩展只改表。
3. **全程可审计**：每步产物配报告（cleaning / alignment / 图表摘要 / 分析注意事项），每个数字可回溯到映射表与原始值。
4. **结论标价**：缺失率、样本量、口径差异与每个数字同行；发现分三档，猜设想明说是猜测。

这套原则不依赖"调查数据"这个具体场景——任何"多源异构数据 → 统计 → 报告"的项目都适用。差异只在细节：你的数据可能是数据库多表 join 而非跨年 CSV，但"先体检、再清洗、映射外置、口径先行、结论分级"的骨架不变。

**练习 9.3**（写作）为图表 `05_web_frameworks.png` 写一段 3–5 句的解读（替代现有 4.5 节），要求包含：首尾数字、缺失率勾连、至少一个替代解释。

**练习 9.4**（结构）把分析报告的 2.2 节缺失率表挪到附录，核心发现前只留一句话提示。评估这一改动对读者的影响，给出你的取舍。

**练习 9.5**（迁移）假设你的下一个项目是"电商平台五年订单数据对齐分析"（表结构逐年变化、字段改名、缺失 各异）。列出从本教材迁移的四步计划与每步最可能踩的坑。

### 参考答案

**9.1** a) "VS Code 使用率从 10.9% 升至 13.4%（2019–2023），是上升最快的编辑器之一；注意该组缺失率 40%–61%，此趋势指作答者中的相对位置。" b) "MySQL 使用率在 2023 年从 28.2% 降至 20.5%（−7.7pp），跌幅超出该组缺失率变化（23.8%→33.8%）能解释的范围，值得关注后续年份是否延续。" c) 直接删掉或改为事实陈述——"前景"是对未来的因果预测，自报抽样数据不支持；可改写为"机器学习在新手中的选择率（11.8%）高于资深组（7.2%）"。

**9.2** a) **可断言**：2020 起缺失 < 0.2%，逐年单调、幅度（每年 1–2pp）远超 CI（±0.5pp），四年方向一致。b) **存疑线索**：6.6% 是事实数字，但它是 2023 新增选项、早年无对应类目，无法参与跨年比较，只能作为 2023 年截面事实描述。c) **方向性观察**：+2.5pp 幅度尚可，但 IDE 组缺失率最高（40%–61%）且 2023 年缺失上跳，幅度接近分母噪声量级——方向可提，幅度不强调。

**9.3** 示例："Flask（26.5% → 27.0%）与 Django（23.9% → 26.6%）五年稳居前二，2020–2022 年两者都到过 33%–37%。2023 年的回落与该组缺失率上升（22.5% → 34.1%）同步，更可能反映分母变化而非使用率下降。另一种解释是框架用户向头部迁移、长尾选项退出问卷可见范围，但数据无法区分两者。其余框架使用率均在 4% 以下，排名五年基本未动。"（首尾数字 ✓ 缺失勾连 ✓ 替代解释 ✓）

**9.4** 优点：核心发现前置、报告更短。风险：读者在 4.5 节读到"回落可能与缺失率同步"时没有表格可查，折扣理由变成无据断言；二次引用者很可能只读正文不翻附录，免责信息丢失。取舍：若读者群是同行分析师（会翻附录、懂口径），前置一句话提示 + 附录明细可接受；若读者群是引用结论的管理层/媒体（只读正文），缺失率表必须留在正文。本报告的实际读者是"可能引用它的人"，维持现状（正文第 2 节）更稳。

**9.5** 四步：① 体检（各年表结构 diff、字段名清单、缺失画像）——坑：电商表常有系统迁移产生的"幽灵字段"（迁移当月双写），先查字段出生/死亡日期；② 清洗（订单状态枚举统一、退款单口径、测试订单剔除）——坑：状态机枚举跨年新增值（如新增"预售"状态）会被对齐管线当成变体合并，需要白名单声明"新值≠变体"；③ 对齐（字段改名映射、度量口径如 GMV 定义变化）——坑：同名不同义比异名同义更危险（"成交额"定义逐年变），value_mapping 思路要扩展成"口径变更表"；④ 统计与报告（同比/环比分母、大促月的季节性）——坑：电商数据强季节性，跨年比较必须对齐月份窗口，且大促样本会扭曲"月度使用率"类指标。骨架相同，细节全是新坑——这正是每章"口径先行"反复强调的原因。
