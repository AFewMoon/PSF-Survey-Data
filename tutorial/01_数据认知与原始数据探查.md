# 第 1 章 数据认知与原始数据探查

> 目标：拿到一套陌生的调查数据后，在写任何一行清洗代码之前，先弄清"这是什么数据、长什么样、有哪些坑"。本章全部操作针对仓库根目录的原始 CSV，**只读不改**。

## 1.1 先问五个问题

任何数据项目开始前，依次回答：

1. **数据是谁生成的？** 本案例是自愿填写的在线问卷（PSF 年度 Python 开发者调查，JetBrains 提供数据）。这决定了它是**自报抽样数据**：受访者不是随机抽样的总体代表，第 6 章会展开其后果。
2. **调查对象是谁？** 用 Python 的开发者，通过 JetBrains/PSF 的渠道发放。渠道本身会引入选择偏差（如 JetBrains 用户可能更多）。
3. **结构是什么？** 每年一份独立问卷，受访者一行、题目一列；多选题会拆成多列。
4. **数据量有多大？** 下表给出各年规模——注意 2020 年后样本量近乎腰斩，这直接影响后续跨年比较的精度。

| 年份 | 原始行数 | 原始列数 | 文件 |
|---|---|---|---|
| 2019 | 47,308+ | 数百 | `2019_python_psf_external_19.csv` |
| 2020 | 37,793+12,554 空行 | 数百 | `2020_2020_sharing_data_outside.csv` |
| 2021 | 23,201 | 数百 | `2021_2021_sharing_data_outside.csv` |
| 2022 | 23,009 | 数百 | `2022_2022_sharing_data_outside.csv` |
| 2023 | 25,324 | 数百 | `2023_2023_sharing_data_outside.csv` |

5. **有没有配套文档？** 有"问题清单"文件（`*_questions_outside.csv`）。**坑**：2020 年的问题清单只有表头没有内容，无法用来核对题目措辞——这就是为什么 2020 年列名中的措辞变体只能靠其他年份推断。

## 1.2 安全读取大 CSV

600 MB 的 CSV 直接 `pd.read_csv` 会很慢且占内存。探查阶段养成三个习惯：

```python
import pandas as pd

# 习惯一：只读前几行看结构
head = pd.read_csv("2023_2023_sharing_data_outside.csv",
                   encoding="utf-8-sig", nrows=5)
print(head.shape)          # (5, 列数)
print(list(head.columns)[:20])

# 习惯二：显式控制缺失语义
# keep_default_na=False：不要让 pandas 把 "NA"、"None"、"N/A" 等自动变 NaN。
# 这一点至关重要：问卷里 "None" 是合法选项（"你用过哪些数据库？"答 None = 不用），
# 若被 pandas 吞成 NaN，"不使用"和"没回答"就混在一起了。
one = pd.read_csv("2023_2023_sharing_data_outside.csv",
                  encoding="utf-8-sig", keep_default_na=False, nrows=1)

# 习惯三：全量读取时按需选列
cols = ["response_id"] + [c for c in head.columns if c.startswith("database.")]
df = pd.read_csv("2023_2023_sharing_data_outside.csv",
                 encoding="utf-8-sig", keep_default_na=False, usecols=cols)
```

三个参数逐条解释：

- `encoding="utf-8-sig"`：原始文件带 UTF-8 BOM。若用 `"utf-8"` 读，第一列名会多出一个隐形 `\ufeff` 前缀，后续所有按列名匹配的代码全部失效。这是 Windows 环境最常见的坑之一。
- `keep_default_na=False`：见上，保护 "None" 等合法取值。本仓库所有读取代码统一带此参数。
- `dtype=str`（清洗阶段使用）：先全部按字符串读入，把"值域"的问题交给后面统一的类型转换步骤，避免 pandas 自动推断出稀奇古怪的混合类型。

## 1.3 两种表头风格：同一份"问卷"，两套命名

把两年的列名打出来对比：

```python
h19 = pd.read_csv("2019_python_psf_external_19.csv", encoding="utf-8-sig", nrows=0)
h23 = pd.read_csv("2023_2023_sharing_data_outside.csv", encoding="utf-8-sig", nrows=0)

print(h19.columns[3])   # 'Django:What web frameworks do you use in addition to Python?'
print(h23.columns[3])   # 'web.frameworks.Django'
```

- **2019 年**：表头是 `选项:完整问题文本` 的格式。优点是语义完整，缺点是列名长达 100+ 字符、含冒号问号、且不同题的选项文本可能相同（同名冲突）。
- **2020–2023 年**：表头是 `前缀.题目.选项` 的点分结构，如 `web.frameworks.Django`。规范、简短，但各年的前缀路径不完全一致（第 4 章详述）。

这 5 年数据要合并，就必须先把两套命名映射到同一套标准列名——这是整个项目清洗+对齐两条管线的存在理由。

## 1.4 多选题的存储形态

问卷多选题"你使用哪些数据库？"（可多选）在 CSV 里被拆成多个二值列：

```
database.PostgreSQL, database.MySQL, database.SQLite, database.None, ...
```

探查一下取值分布：

```python
db = pd.read_csv("2023_2023_sharing_data_outside.csv", encoding="utf-8-sig",
                 keep_default_na=False, usecols=lambda c: c.startswith("database."))
print(db.shape)                 # (25324, 12) —— 12 个二值列 = 12 个选项
print(db["database.PostgreSQL"].value_counts())
# 取值基本只有 '' 和 'PostgreSQL' 两种 —— 每列只"记录自己"
print((db == "PostgreSQL").sum())   # 1 的个数 = 该选项被勾选的人数
```

理解这个形态是本项目的关键前提：

- 每个选项一列，取值要么是空串（未勾选）要么是选项文本本身（勾选）——**列名在列里重复了一遍**。
- 清洗时要做"二值化"：把 `'' / 'PostgreSQL'` 变成 `0 / 1`（第 3 章）。
- 分析时该组的使用率 = 各列均值，且**合计可以超过 100%**（一人可同时用多个数据库）。
- "None" 选项也是一列，表示"什么都不用"，它同样参与统计但在排名时通常要排除。

## 1.5 快速体检清单

对每个原始文件执行一遍下面的体检（可以直接抄去你的下一个项目）：

```python
import pandas as pd

def health_check(path: str) -> None:
    df = pd.read_csv(path, encoding="utf-8-sig", keep_default_na=False, dtype=str)
    n, m = df.shape
    print(f"文件: {path}")
    print(f"规模: {n:,} 行 × {m} 列")

    # 1. 全空行（完全没填任何题的提交）
    empty_rows = int((df == "").all(axis=1).sum())
    print(f"全空行: {empty_rows:,}")

    # 2. 全空列（整列没有一个人答）
    empty_cols = int((df == "").all().sum())
    print(f"全空列: {empty_cols}")

    # 3. 完全重复的行
    print(f"完全重复行: {int(df.duplicated().sum()):,}")

    # 4. 列名冲突（重名或仅大小写不同的列）
    lowered = [c.lower() for c in df.columns]
    dup_names = len(lowered) - len(set(lowered))
    print(f"重复列名: {dup_names}")

    # 5. 每列缺失率分布（缺多少列超过 50% 缺失）
    miss = (df == "").mean()
    print(f"缺失率>50% 的列: {int((miss > 0.5).sum())} / {m}")

health_check("2020_2020_sharing_data_outside.csv")
# 实际输出（节选）：
# 规模: 50,347 行 × 数百列     ← 注意：含 12,554 全空行！
# 全空行: 12,554              ← 2020 年特有问题，清洗时必须删
# 全空列: 若干                 ← 有些题整年没人答
```

2020 年的体检结果暴露了三件事，分别对应清洗管线的三个步骤：

1. 12,554 个全空行 → 删全空行；
2. 若干全空列 → 删全空列；
3. 列名风格与其余年份不同 → 列名规范化（第 3 章）。

## 1.6 数据"物理形态"之外：理解调查流程

最后一步认知工作在代码之外，但决定后面所有统计口径：

- **问卷有跳转逻辑**（branching）。2019 年把"是否以 Python 为主语言"这类题放在选答分支里，导致 2019 年 `is.python.main` 缺失约 25%、`use.python.most` 缺失 48.2%。缺失不是数据损坏，而是问卷设计的结果——第 6 章会讲为什么这让跨年比较必须打折扣。
- **多选题只展示给部分受访者**（show-if 条件），所以框架/数据库/IDE 组在 2020–2022 年也有两至四成人没作答。统计这些组时的分母是"至少勾选一项（含 None）的人"，不是全体受访者。
- **选项逐年增删**。2023 年 `use.python.most` 新增 "Academic research"、"Data engineering" 等独立选项，早年这些回答散落在 "Other" 里。选项拆分会人为压低旧类目的占比，制造虚假趋势。

把这三点写进项目笔记。数据认知阶段的产出不是代码，而是**一张"已知问题清单"**——本仓库它体现在 `AGENTS.md` 与分析报告第 2 节里。

## 1.7 本章要点

- 拿到数据先回答：谁生成的、对象是谁、什么结构、多大、有没有文档。
- 大 CSV 探查用 `nrows=` / `usecols=`；读取统一 `encoding="utf-8-sig", keep_default_na=False`。
- 2019 与 2020–2023 是两套表头方案，合并前必须统一命名。
- 多选题 = 每选项一列的二值矩阵，"None" 是合法选项。
- 全空行（2020 年 12,554 个）是真实的上游质量问题，体检清单能先于清洗发现它。
- 理解问卷跳转与选项增删，缺失率和口径差异要先有假设再动手。

**练习 1.4**（思考）问卷中 `is.python.main` 一题的选项包括 "Yes"、"No, I use Python as a secondary language"。若在读取时不加 `keep_default_na=False`，pandas 默认会把哪些值变成缺失？这会如何歪曲"主语言比例"的估计？

### 参考答案

**1.1** 2019 年没有任何列以 `database.` 开头——它用的是 `选项:问题文本` 命名，数据库题的列长这样 `PostgreSQL:Which database(s) do you regularly use, if any?`。点分前缀是 2020 年起的方案。这个观察是第 3 章 `style == "question"` 分支存在的原因。

**1.2** 第一列名会显示为 `'\ufeffresponse_id'`（或 BOM 黏在首个字段上）。肉眼不可见但字符串比较不相等，`df.columns[0] == "response_id"` 返回 False。解决即用 `utf-8-sig`。

**1.3** 2019 年全空行很少（几乎没有），但重复列名较多。来源：不同问题的选项文本相同（如 "None" 出现在数据库、框架、IDE 等许多多选题里），拼上各自的问题文本后并不重名，但仅用选项 slug 化后会撞名；清洗管线因此有 `__dup` 后缀机制。以 2019 而言真正同名冲突的是清洗过程中产生的中间命名。

**1.4** 默认 NA 值集合包含 `"None"`、`"NA"`、`"N/A"`、`"nan"`、`"null"` 等。"Yes" 不会受影响，但类似 "None" 的选项（如数据库题的 None）会变 NaN。对 `is.python.main` 的直接影响：缺失比例被高估、且"未用 Python"与"没回答"无法区分，主语言/副语言比例的分母（有效样本）被错误压缩，比例本身也可能失真（若 NaN 在 `normalize="index"` 下被排除，则比例相对不变，但有效样本量报告会错）。
