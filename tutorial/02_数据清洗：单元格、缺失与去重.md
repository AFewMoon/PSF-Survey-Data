# 第 2 章 数据清洗：单元格、缺失与去重

> 目标：理解 `clean_survey.py` 上半部管线——缺失口径设计、单元格规范化、全空行/列删除、按内容去重。清洗的原则：**每一步都可解释、可撤销、可审计**。

## 2.1 清洗管线的全景

`clean_survey.py` 对每个年份执行固定顺序的六步：

```
读取(dtype=str) → 列名规范化 → 单元格规范化 → 删全空列/行 → 去重复行/列 → 多选归一与类型转换
```

顺序是有讲究的：

- 列名规范化放最前：后面所有操作（找多选列、判缺失）都依赖规范的列名。
- 全空行/列的删除放在单元格规范化之后：只有先把 `""`、`"NA"`、`"nan"` 等都归成统一的空串，"全空"的判定才可靠。
- 去重放在删空之后：先把噪声行清掉，重复行的判定才不会被空行干扰（否则 12,554 个空行会被"去重"成 1 个，掩盖真实数据质量问题）。
- 类型转换放最后：前面保证值域干净，转换才安全。

## 2.2 缺失口径：一张白名单

清洗的第一个决定是：**哪些字符串算"没回答"？**

```python
# 统一缺失标记（注意 'None' 是合法选项文本，不作缺失处理）
MISSING_TOKENS = {"", "na", "n/a", "nan", "null", "none.", "unknown"}
```

逐条看设计意图：

- `""`：空串，占绝大多数。
- `na / n/a / nan / null`：常见的显式缺失标记，小写归一后匹配。
- `none.`（带点）：来自表头或系统生成的占位文本；注意**不带点的 `none` 被刻意排除**——"None" 在多选题里是合法回答（= 什么都不用），绝不能当缺失吞掉。
- `unknown`：调查里出现的"不知道"类回答。

大小写与空白差异由 `is_missing` 处理：

```python
def norm_ws(text: str) -> str:
    return re.sub(r"\s+", " ", str(text)).strip()

def is_missing(value: str) -> bool:
    return norm_ws(value).lower() in MISSING_TOKENS
```

`norm_ws` 把连续空白压成单个空格再去首尾——原始问卷数据里大量存在 `"  N/A  "`、`"Na\n"` 这类脏值，先用统一函数归一，再查白名单。**归一逻辑永远走 `norm_ws`/`norm_key`，不要在各个地方零散写正则**——本项目编码规范中明文要求，原因很简单：散落的正则迟早互相不一致。

## 2.3 单元格规范化

每个单元格依次经历：压空白 → 统一标点 → 缺失归空。

```python
def clean_cell(value: str) -> str:
    """单元格规范化：去首尾空白、压缩内部空白、统一连字符/省略号、缺失标记归空。"""
    s = norm_ws(value)
    s = s.replace("\u2013", "-").replace("\u2026", "...")   # en-dash → 连字符；… → ...
    return "" if is_missing(s) else s
```

为什么要替换 `\u2013`（en dash "–"）和 `\u2026`（"…"）？

- 不同年份问卷里，区间写法混用了 `1-2 years` 与 `1–2 years`（en dash）。肉眼几乎看不出差别，但 `==` 比较和 `groupby` 都会把它们当成两个不同取值，统计表里凭空多出一行。
- 省略号同理：`PyCharm Professional Edition…`（截断省略）与 `PyCharm Professional Edition...`（三个句点）必须归一，否则对齐阶段会多出一个假变体。

教训：**跨表合并之前，先把"人眼看不出差别、机器认为不同"的字符统一掉**。常见黑名单还包括弯引号（`''""`）、全角标点、不换行空格（`\u00a0`）——对齐管线的 `PUNCT_TRANS` 表（第 4 章）是完整版。

还有一类只靠规则很难穷举的脏值：上游导出时把 `<br />` 直接删掉，留下 `From timeto time` 这种粘连文本（正确写法是 `From time to time`）。规则管线靠人工往 `clean_cell` 里加特例，LLM 管线则让模型在读样本值时把它作为一条"单元格改写"决策记录下来（第 10 章）。

`clean_cell` 的应用方式：

```python
df = df.apply(lambda s: s.map(clean_cell))
```

`apply` 逐列、`map` 逐格，6 个年份合计约 18 万行、两千余列，纯 Python 循环到这里是可接受的（一次性管线，不是热路径）。若数据量更大，可改为向量化：`s.str.strip().str.replace(...)` 再配合 `s.isin(MISSING_TOKENS)` 掩码，速度能快一个量级——教材示例保留逐格版本是为了可读性。

## 2.4 删除全空列与全空行

```python
# 删除全空列 / 全空行
empty_cols = [c for c in df.columns if (df[c] == "").all()]
df = df.drop(columns=empty_cols)
empty_rows = df.index[(df == "").all(axis=1)]
df = df.drop(index=empty_rows).reset_index(drop=True)
```

三个细节：

1. **为什么只删"全空"而不删"高缺失"？** 一列缺 95% 仍可能是有信息（比如只向极小众受访者展示的题目）；而一列 100% 空，只能说明问卷配置了该题却无人看到它，保留没有价值。删除标准要从严，"高缺失"留给分析阶段结合缺失机制（第 6 章）判断。
2. **`(df[c] == "")`** 能这么写，是因为缺失已统一为空串、且全表是字符串类型。若缺失是 NaN，要写 `(df[c].isna().all())`；两种写法不可混用——这正是本仓库坚持"缺失一律空串"约定的原因：**全表只用一套缺失判定逻辑**。
3. **`reset_index(drop=True)`**：删行后索引出现空洞，统一重置连续索引，避免后续 `.loc` 语义混乱。

2020 年实测：删掉 12,554 个全空行后剩 41,908 行，再去重删掉 4,115 行，最终 37,793 行。这些空行来自上游导出错误（一份空模板被重复写入），如果保留，任何按年的比例统计都会被严重稀释——真实回答 37,793 份，名义样本却有 54,462 份，分母虚高 44%。

## 2.5 去重：按内容，不按 ID

```python
# 删除完全重复行 / 重复列（按内容判定，保留首个）
dup_rows = int(df.duplicated().sum())
df = df.drop_duplicates().reset_index(drop=True)
dedup_cols: list[str] = []
seen: dict[tuple, str] = {}
for col in list(df.columns):
    key = tuple(df[col].tolist())
    if key in seen:
        dedup_cols.append(col)
    else:
        seen[key] = col
df = df.drop(columns=dedup_cols)
```

**重复行**：`df.duplicated()` 对所有列完全一致的行标记 True。保留首个、删除其余。注意这里没有 `response_id` 可依——若数据带唯一 ID，重复判定应改为 `duplicated(subset=["response_id"])` 并检查同 ID 行是否内容冲突（冲突则说明是数据损坏，需要人工介入，而不是简单去重）。

**重复列**：判定标准是"整列取值完全相同"（`tuple(df[col].tolist())` 作哈希键）。这里有一个必须理解的陷阱：

> 整列相同 ≠ 语义相同。

- 安全的情形：多选题里两个选项从不被人同时勾选、且取值模式碰巧一致（例如某两个选项从未被勾选，两列全 0）——合并无信息损失。
- 危险的情形：两个不同选项恰好取值分布一致（例如各只有 3 人勾选且恰好是同一批人不可能发生，但"从未被勾选"与"整列缺失"会看起来一样）。

本仓库的做法是**保守去重**：只删完全相同的列并在报告中记录数量（`dropped_dup_cols`），对可疑情形宁可保留。同时，列名重复（同名冲突）不在此步处理——那发生在列名规范化时用 `__dup` 后缀消歧（第 3 章），两件事不能混淆：**内容去重是删数据，命名消歧是改标签**。

`tuple(df[col].tolist())` 作为字典键的写法有性能隐患：对 50,000 行的列，建 tuple 要复制全部数据。若列数很多，可先对每列算一个哈希（如 `hashlib.md5(col_bytes)`）再比较；或者只对"数值指纹完全一致"的候选列做逐元素二次确认。教材保留朴素版本，因为本项目每年几百列、只跑一次。

## 2.7 本章要点

- 清洗六步顺序固定：列名 → 单元格 → 删空 → 去重 → 类型。顺序本身是设计。
- 缺失口径用白名单 + `norm_ws` 归一；`None` 是合法选项，不能进缺失名单。
- en dash、省略号等"隐形异体字符"在合并前必须统一。
- 只删全空行列，不删高缺失行列——从严标准留给分析阶段。
- 去重区分内容去重与命名消歧，保守执行并全程记录。
- 清洗报告是管线的"黑匣子"，扩展后必读。

**练习 2.5**（设计）数据带唯一 `response_id`，且发现 300 对同 ID 行内容不同。给出你的处理方案与理由，以及哪些操作必须先做才能做这个判断。

### 参考答案

**2.1** 多选题列 `database.None` 的取值 `None` 是"不使用任何数据库"的合法回答；若把 `none` 加入缺失名单，这一列会被整列清空，"不使用者"全部变成"缺失者"，使用率统计的分母分子双双失真。带点的 `none.` 只匹配系统占位文本，不会误伤。场景：`database.None` 列里勾选者的取值就是字符串 `None`。

**2.2** ① 连续多个空格 `"a    b"` → 前者压成 `"a b"`，后者原样；② 制表符/换行夹在中间 `"a\tb\nc"` → 前者统一为 `"a b c"`，后者只处理不了 `\t`（若 replace 只处理空格）；③ 首尾是换行而非空格时 `strip()` 版本能去掉首尾但中间不处理。核心差异：`\s+` 一次性覆盖所有空白字符且处理"连续出现"。

**2.3** 2020 年全空行在规范化前后都表现为全空（它们本来就是真空行），表面结果相同；但这个顺序依赖"空 = 空串"这一事实。若上游缺失写的是 `"N/A"`，规范化前的"全空行"检测会漏掉这些行，它们混入后续去重步骤，`duplicated()` 会把 12,554 行重复空模板行"去重"成 1 行，`dropped_dup_rows` 数字虚高而 `dropped_empty_rows` 归零——两个统计口径都被破坏。结论：删空必须在归一之后，且报告数字是排序正确性的证据。

**2.4** 参考实现：

```python
def clean_frame(df: pd.DataFrame) -> pd.DataFrame:
    out = df.copy()
    for c in out.columns:
        s = out[c].astype(str).str.replace(r"\s+", " ", regex=True).str.strip()
        s = s.str.replace("\u2013", "-", regex=False).str.replace("\u2026", "...", regex=False)
        out[c] = s.mask(s.str.lower().isin(MISSING_TOKENS), "")
    return out
```

验证：构造含 `"  N/A "`、`"a  b"`、`"1–2 years"` 的小 DataFrame，与逐格版本逐元素 `assert` 相等。注意 `mask` 是一次完成"匹配即替换为空串"的向量化手法。

**2.5** 方案分三层：① 先完成单元格规范化与缺失归一（否则无法判断"内容不同"是不是 `"N/A"` vs 空串的假差异）；② 同 ID 行逐列对比，统计冲突列数：仅 1–2 列冲突且集中在自由文本题，视为笔误保留首条或标记待审；大量列冲突视为上游重复导出错误，全部降级为"存疑样本"剔除并单独报告；③ 无论哪种，都要把判定标准、涉及 ID 清单写进清洗报告，禁止静默删除。若冲突原因不明，优先回源文件核查而非在清洗层拍板。
