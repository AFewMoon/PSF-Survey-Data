# 三种部署形态的合规边界：本地私有 / 云端 API / 纯规则

生成时间：2026-10-29
范围：2019–2024 PSF 开发者调查的清洗与跨年对齐；只讨论"模型参与判断"这一形态下的数据边界，
不涉及调查数据本身的采集与再分发。

## 结论

1. **本次实验用本地私有部署**：模型权重在本机，判断请求不出机器，这是唯一不需要额外审查就能开工的形态。
2. **决策缓存入版本库**，与既有 `llm/decisions/`（已入库 304 个 JSON）保持同一规则——它记录的是判断依据，
   不是原始回答。
3. **模型权重不入版本库**：`pangu/models/` 与 `*.gguf` 已写入 `.gitignore`。理由是体积（本机两份共 5.29 GB）
   和上游许可，而不是保密。
4. **云端 API 形态暂不采用**：当前规模下本地已够用，上云换不到质量，却要多一层数据出域与合同审查。

## 一、模型到底看到了什么

这是所有合规讨论的前提。管线从不让模型接触数据本体，送入提示词的字段固定为四类：

| 送进提示词 | 例子 | 是否含个人信息 |
|---|---|---|
| 列名（清洗后） | `language.usage.Python` | 否 |
| 结构特征 | 非空率 92.3%、基数 41 | 否 |
| 类别取值（选项写法） | `Amazon Web Services`、`AWS` | 否，属问卷预设选项 |
| 至多 6 个截断样本值 | 类别列的取值，单值截断 | 类别列无风险；自由文本列不送原文 |

自由文本列只保留结构特征（非空率、基数、主取值占比），原文不进提示词——这一条写在
`llm/README.md` 的"工作方式"里，也是 `profiles.py` 的实现约束。

因此三种形态的差异不在"送了什么"，而在"送给谁、留不留痕、能不能重跑"。

## 二、三种形态对比

| 维度 | 本地私有部署（本次） | 云端 API | 纯规则管线 |
|---|---|---|---|
| 数据出域 | 不出机器 | 提示词内容发往第三方 | 不出机器 |
| 需要的前置手续 | 无（内部实验） | 数据处理协议、留存期约定、跨境评估（若服务在境外） | 无 |
| 版权归属 | 原始数据仍属 JetBrains/PSF；脚本与文档 GPL-3.0；权重按上游许可，不再分发 | 同左，另需核对服务条款对输入内容的再使用约定 | 同左，且无可疑第三方 |
| 决策文件入库 | 可以：只含列名、取值写法与判断理由 | 需先确认服务条款是否允许留存输出 | 无模型输出，只有规则与映射表 |
| 可复现性 | 强：模型版本用 digest 固定，缓存命中即零调用 | 弱：模型版本随时变动，需自行固定快照 | 最强：纯确定性 |
| 边际成本 | 电费与时间 | 按 token 计费 | 零 |
| 覆盖面 | 110 列（4B）/ 判断层可用（7B） | 同模型能力 | 153 列（人工），规则无法覆盖跨年改名 |

## 三、决策文件入库的边界

`decisions/` 下的 JSON 是"判断依据"而不是"数据副本"。单个文件的实际内容：

- `stage` / `model` / `model_digest` / `prompt_version` / `input_hash`：可追溯，用来判定缓存是否失效；
- `payload_summary`：本批涉及的列名与前若干字，例如 `year: 2019, n: 4`；
- `response`：模型给出的 `kind` / `group` / `option` / `missing_tokens` / 一句理由；
- `duration_s` / `output_tokens` / `fallback`：成本与降级标记。

没有任何一行原始回答落在这里。这也是它可以直接入库的理由：它让"某年某列为什么被这样清洗"
可以被复查，而复查成本是打开一个 JSON。

需要注意的两点：

1. 如果将来把同一套管线接到**非公开数据**（例如企业内部问卷），`decisions/` 就必须移出版本库或加密，
   因为 `payload_summary` 里仍会带列名与少量样本值。
2. 模型的 `reason` 字段是自然语言，可能把样本值写进理由里。当前实测样本是问卷选项，无风险；
   换成自由文本数据前要先抽查几份决策文件再定。

| 云服务输出 | 依服务条款 | 本次未使用 |

权重不入库已经落到 `.gitignore`（`pangu/models/`、`*.gguf`），避免一次误提交把 5.29 GB 权重推进历史。

## 五、什么时候才需要上云

判断标准是"本地跑不动"而不是"云上更强"：

- 单个模型跑完六年清洗的时间超过可接受窗口（当前 7B 跑 2019 一年即按小时计）；
- 需要 MoE 大模型（如 2.0-Flash 的 40.7 GiB 档）——本机可用内存 6.17 GiB，差 6 倍以上；
- 判断量级从"每年几十批"涨到"每天数千批"。

真要走云端，需要先补三件事：数据出域清单（送到哪里、留多久）、合同条款对输入内容的再使用约定、
以及把 `decisions/` 的留存策略改成"只留报告、不留原文摘要"。
